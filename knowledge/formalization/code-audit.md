## Finite quantum clock boundary

For finite-dimensional `d`, finite Hermitian matrix clock Hamiltonian and time operator cannot satisfy exact global canonical commutation `[T,H] = iℏ I` when `ℏ ≠ 0`: cyclicity of finite matrix trace gives `tr([T,H]) = 0`, while `tr(iℏ I) = iℏ · card(d) ≠ 0` for nonempty `d`. This is a short formalizable linear-algebra theorem over the `MState`-adjacent matrix substrate; it is a no-go for that exact algebra, not for all finite clocks, relational time, or POVM clocks. The inspected `MState.nonempty` derives nonemptiness of the index type from trace-one state existence.

A periodic finite clock or a clock with a finite POVM of readings remains available. Its labels wrap or resolve only finitely many distinguishable outcomes; it does not provide an ideal real-line clock with continuous orthogonal time states and exact canonical generator assumed in some ideal Page–Wootters constructions. The idealization and finite model are different premises. A finite toy model is faithful only for a theorem whose assumptions and operational predictions are preserved by the finite replacement; no such correspondence has been shown here. Do not describe a cyclic finite clock result as proving the unrestricted ideal-clock equivalence.

## Minimum viable substrate recommendation

For a discrete finite clock with finite outcomes, the smallest viable Lean substrate is likely Physlib `MState` plus its finite matrix/Hermitian foundations and `POVM` module, with a new clock layer defining a finite outcome space, POVM, specified joint state/constraint, conditional system states, and explicit predictions. This supports exact finite probability calculations and finite-resolution comparisons. The target paper must first be reduced to a theorem whose hypotheses survive discretization; no automatic bridge from an ideal clock follows.

For exploratory finite examples and assumption-ablation countermodels, Python or a SAT/SMT finite-model tool is the faster first step. This inspection did not establish a current model-finding integration in the repository. Use Lean after the model/signature and lemma stabilize, especially for the trace obstruction and algebraic invariants. Use the Isabelle Schutz locale only for questions directly about event/path/betweenness assumptions; it is not a substitute for a quantum clock model.
